# ESP32 双模式三组姿态识别设计

## 目标

以 `D:\机器人\ESP32` 的 ESP-IDF 外设工程为硬件模板，在 `D:\机器人\视觉` 保留既有 K230 三组动作定义的前提下，增加：

1. 电脑端 RTX 5060 高精度姿态识别模式；
2. ESP32-S3 + OV2640 本地姿态识别模式；
3. 两种模式共用动作 ID、中文标签、COCO-17 关键点语义、置信度和稳定帧规则；
4. Wi-Fi 只作为可选视频预览、调试和配置通道，本地模式不依赖 Wi-Fi。

## 动作契约

动作 ID 和标签必须与 `D:\机器人\视觉\pose_recognition.py` 以及三个团队包保持一致：

| ID | 标签 | 中文 | Team 1 | Team 2 | Team 3 |
| ---: | --- | --- | :---: | :---: | :---: |
| 0 | `unknown` | 未识别 | 否 | 否 | 否 |
| 1 | `big_stand` | 大字站 | 是 | 是 | 是 |
| 2 | `bow_step` | 弓箭步 | 是 | 是 | 是 |
| 3 | `double_hands` | 举双手 | 是 | 是 | 是 |
| 4 | `squat` | 蹲下 | 是 | 是 | 是 |
| 5 | `attention` | 立正 | 是 | 否 | 否 |
| 6 | `knee_raise` | 单膝抬起 | 否 | 是 | 否 |
| 7 | `one_arm_side` | 单臂侧平举 | 否 | 否 | 是 |
| 8 | `one_hand_up` | 单手举手 | 是 | 否 | 否 |
| 9 | `crossed_arms` | 双臂交叉 | 否 | 否 | 是 |
| 10 | `bend_forward` | 俯身 | 否 | 是 | 否 |

编译期或启动期组别白名单固定为：

```text
Team 1: (1, 2, 3, 4, 5, 8)
Team 2: (1, 2, 3, 4, 6, 10)
Team 3: (1, 2, 3, 4, 7, 9)
```

未知动作、关键点置信度不足、人体不完整或多个规则冲突时，统一返回 `unknown`，不强行选择最高分动作。

## 总体架构

```text
                         ┌──────────────────────────────┐
                         │ shared/pose_contract         │
                         │ ID、标签、三组白名单、JSON   │
                         └──────────────┬───────────────┘
                                        │
              ┌─────────────────────────┴─────────────────────────┐
              │                                                   │
┌─────────────▼─────────────┐                     ┌────────────────▼───────────────┐
│ PC 高精度模式              │                     │ ESP32 本地模式                  │
│ ESP32 MJPEG/USB 视频       │                    │ OV2640 + ESP-DL Pose           │
│ RTX 5060 + RTMPose         │                   │ COCO-17 关键点                  │
│ Python 几何分类/稳定器     │                    │ C/C++ 几何分类/稳定器            │
└─────────────┬─────────────┘                    └────────────────┬───────────────┘
              │                                                   │
              └──────────────────┬────────────────────────────────┘
                                 ▼
              `pose_result`：当前动作、稳定动作、置信度、关键点、FPS
                                 │
                    可选 UART / HTTP / LCD / 调试输出
```

### 电脑端

电脑端使用高精度姿态模型产生 COCO-17 关键点。模型适配层只负责检测和坐标统一；动作判断继续使用现有规则语义，避免改变三组动作的含义。默认使用 RTMPose-m，保留模型配置入口以便后续切换 RTMPose-l 或 ViTPose。

电脑端输入支持：

- ESP32 `/stream` MJPEG 视频；
- 本机 USB 摄像头；
- 本地视频文件，用于回归测试。

电脑端输出支持：

- 画面叠加骨架和动作名称；
- JSONL 文件记录；
- 通过串口向 ESP32 发送稳定动作结果；
- 可选 HTTP 调试接口。

### ESP32 本地端

ESP32 端启用 `D:\机器人\ESP32\components\BSP\CAMERA` 中的 OV2640 驱动，使用 PSRAM 帧缓冲获取 JPEG 或 RGB 图像。姿态模型采用 ESP-DL 可部署的量化模型，输入缩放到固定尺寸，输出 COCO-17 关键点。

ESP32 本地端只做单人、静态姿态识别和短帧稳定，不承担完整视频编码、复杂时序模型或多人的精细跟踪。三组动作共用一个姿态模型，通过 Team 白名单降低冲突。

本地第一阶段以“无 Wi-Fi 的低频静态识别验证”为目标。ESP-DL 官方 COCO Pose 示例在 ESP32-S3 上的 YOLO11n-Pose 计算量较大，不能据此承诺实时视频帧率；若实测速度不满足要求，后续再用电脑端教师模型蒸馏出更小的专用关键点模型。电脑端高精度模式不受此限制。

本地模式的正常运行路径不调用 Wi-Fi。Wi-Fi 初始化、网页服务器和 `/stream` 预览属于可配置的调试功能，默认可关闭。

## 数据契约

电脑端和 ESP32 本地端都产生如下逻辑字段：

```json
{
  "task": "pose",
  "team": 1,
  "pose_id": 1,
  "pose": "big_stand",
  "pose_cn": "大字站",
  "confidence": 0.92,
  "stable": true,
  "stable_pose_id": 1,
  "stable_pose": "big_stand",
  "stable_pose_cn": "大字站",
  "fps": 20.0,
  "source": "esp32_local"
}
```

UART 与现有 K230 通道兼容时继续使用：

```text
主机发送：START\n
设备返回：RESULT {json}\n
```

新增的电脑端动作结果发送不能破坏现有 K230 帧协议；若两者同时存在，必须通过独立串口或显式模式选择隔离。

## 分类和稳定策略

### 关键点规范

统一使用 COCO-17 顺序：鼻子、双眼、双耳、双肩、双肘、双腕、双髋、双膝、双踝。所有几何计算先使用人体框和肩宽、髋宽、躯干长度做归一化，左右镜像视为同一动作。

### 规则来源

电脑端先复用现有 `PoseClassifier` 的动作条件和优先级；C/C++ 端按同一规则建立独立实现，不直接依赖 Python。规则必须覆盖三组共享动作和各组专属动作，并在关键点缺失时返回 `unknown`。

### 稳定判定

保留现有连续帧去抖语义：只有最近窗口内的结果全部一致且非 `unknown`，才更新 `stable_pose`。人体丢失、关键点质量不足或动作切换时清空当前稳定动作，防止沿用旧结果。

## 运行模式

```text
LOCAL：OV2640 → ESP-DL → C/C++ 分类器；不启用 Wi-Fi
PC：摄像头视频 → RTX 5060 → Python 分类器；串口可选
K230：保留现有 K230 → UART2 → ESP32 网关路径
```

启动时通过配置选择唯一主视觉源，禁止 LOCAL、PC、K230 三条路径同时写入同一个视觉状态，避免结果互相覆盖。

## 错误处理

- 摄像头初始化失败：输出明确错误码，视觉状态为 `unknown`，其他外设继续启动。
- 模型文件缺失或加载失败：本地模式进入禁用状态，不伪造动作结果；网页/串口报告模型错误。
- PSRAM 不足：禁止启动姿态任务，保留低功能摄像头或设备控制能力。
- 关键点置信度不足：返回 `unknown`，不复用上一帧的非稳定动作。
- Wi-Fi 断开：LOCAL 模式不受影响；PC 模式报告视频源断开并停止发送旧结果。
- UART 发送失败：保留本地识别结果，统计丢包，不阻塞摄像头采集任务。

## 测试范围

1. 三组动作 ID、标签和白名单契约测试；
2. 电脑端对合成 COCO-17 骨架的 18 个组内动作/未知动作测试；
3. 左右镜像、关键点缺失、遮挡和冲突规则测试；
4. 稳定帧、丢人和动作切换回归测试；
5. PC 视频输入、JSONL 输出和串口协议测试；
6. ESP32 摄像头初始化、模型加载失败、LOCAL 无 Wi-Fi 启动测试；
7. 真实摄像头下每组 6 个动作各保持 3 秒，检查 LCD、串口和 JSON 结果；
8. 三种视觉源模式互斥测试。

## 非目标

- 不将 RTMPose、MediaPipe 或 ViTPose 完整移植到 ESP32；
- 不在 ESP32 上实现多人姿态跟踪；
- 不修改三组动作的 ID、名称或选择集合；
- 不删除现有 K230 UART2 视觉网关能力；
- 不把 Wi-Fi 作为本地模式的必需依赖。
